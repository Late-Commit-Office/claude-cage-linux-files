感谢复核，这处确实是上一版自查时引入的问题。已在 `0.2.8` 中按最小改法修复：

- **移除跨任务清理**：删除 `remove_stale_partials()` 及其在 `open_downloads()` 中的调用，导出不再扫描或删除 `Downloads` 中的任何其他文件，无论文件名是否符合 `.<任务 id>.partial` 格式。
- **保留当前任务的清理**：任务失败或取消时，只删除本任务以 `O_CREAT | O_EXCL` 创建的临时文件（`run_export()` 的 `finally`），逻辑不变。插件进程在导出途中被结束时，临时文件会留在原处，由用户自行处理。
- **回归测试**：在下载目录中预放两份符合旧清理规则的文件（一份修改时间设为 1970 年，一份为新文件），完成一次无关导出后，确认两份文件都在、内容和修改时间未变，目录中只多出导出的文件。该测试在 `0.2.7` 上失败，在 `0.2.8` 上通过。

PR 描述中的版本号已同步更新。
